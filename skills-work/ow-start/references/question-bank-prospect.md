# Question bank: prospect mode

For scoping a possible client. Each question fills one field of the intake record, so coverage can be scored afterwards. The default priority is a starting point: prep raises or lowers it from what the attached material already answers, and keeps at most three must-asks per block.

| Field | Block | Default | Good to send ahead |
|---|---|---|---|
| `trigger` | Open (0–2) | must-ask | no |
| `timeline` | Open (0–2) | must-ask | yes |
| `current_process` | Problem (2–8) | must-ask | no |
| `volume` | Problem (2–8) | must-ask | yes |
| `pain` | Problem (2–8) | must-ask | no |
| `owners` | Problem (2–8) | if-time | no |
| `systems` | Systems (8–13) | must-ask | yes |
| `data_condition` | Systems (8–13) | must-ask | no |
| `regime` | Systems (8–13) | must-ask | no |
| `data_records` | Systems (8–13) | if-time | no |
| `success` | Success (13–17) | must-ask | no |
| `budget` | Success (13–17) | must-ask | no |
| `decision` | Success (13–17) | must-ask | yes |
| `fit_risks` | Success (13–17) | if-time | no |
| `next_step` | Read back (17–20) | must-ask | no |

Twelve must-asks by default. `trigger` and `timeline` share the opening exchange ("why now, and by when?").

## trigger
"What made you reach out now, and not six months ago?"
- If vague: "Was there a moment it tipped over? What happened that week?"

## timeline
"Is there a date this has to work by? What happens if it slips?"
- If vague: "Where does that date come from?"

## current_process
"Walk me through the last time this happened, start to finish."
- If vague: "What was the very first thing someone did? And then?"

## volume
"How often does this happen, and how many?"
- If vague: "Can you give me a number, even a rough one? Per day or per week?"

## pain
"What happens when it goes wrong? Who finds out, and how?"
- If vague: "When did that last happen, and what did it cost?"

## owners
"Who touches it first? Who's the last person?"
- If vague: "Is that one person, or whoever is free?"

## systems
"What tools does this touch today?"
- If vague: "Where does the information start, and where does it end up?"

## data_condition
"Is the data clean, or does someone fix it by hand? Is anything sensitive in it?"
- If vague: "When did someone last have to correct it, and what was wrong?"

## regime
"Is there any rule or audit this has to satisfy?"
- One plain question. A clear "no" removes all compliance wording from everything written for this client.

## data_records
"What has to be kept, for how long, and who asks for it?"

## success
"Six months from now it works perfectly. What number changed?"
- If vague: "What would you stop doing, or stop worrying about?"

## budget
"Is there a budget range set aside, or are we building the case for one?"
- If vague: "Is there a figure above which this needs someone else's sign-off?"

## decision
"Besides you, who has to say yes, and what would make them say no?"
- If vague: "Who signed off the last thing like this you bought?"

## fit_risks
"Have you tried to fix this before? What happened?"

## next_step
"I'll send a written recap by <date>. Who else should read it?"
