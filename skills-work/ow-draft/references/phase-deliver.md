# `/ow-draft-deliver`: the signed-off candidate, exported and delivered

Run step 0 and the resume step (`references/routing-and-resume.md` §1); the steps are the `/ow-draft-deliver` row of its step table. Schema: `references/draft-files-schema.md` §8. What may leave the machine: `references/delivery-rules.md`.

## 1. The gates (each refuses; nothing is written)

1. **Already delivered** (the newest candidate's entry records `push`): `Nothing to do: <C-n> was delivered on <date>.`, `Nothing was written.` Its exports are never made again.
2. **No sign-off of the newest candidate**: `Refused: no sign-off of <C-n>, the newest candidate.`, `Nothing was written.`, `Fix: sign it off with -signoff <C-n>.`, and the NEXT `use ow-draft-signoff C-n on drafts/<ws>/DR-nn-<slug>/`.
3. **Client comms with no client approval of that candidate**: `Refused: <C-n> has no client approval.`, `Nothing was written.`, `Fix: record it with -signoff --client <C-n> once the client approves.`, and the NEXT `use ow-draft-signoff --client C-n on drafts/<ws>/DR-nn-<slug>/`.
4. **The handling level**, read again now as a union, resume included: `profile.md`'s default, the brief's `handling:` and `banner_text`, the `intake.yaml` and `plan.yaml` `handling:` keys of the draft's client, of every client whose workstream an item cites and of every client a marketing draft names under a permission, and every cited file with a banner (an `inbox/` file is the draft folder's own); a cited file that cannot be read or does not parse counts as a level set. A level set anywhere means no push and no repository copy: the exports and the say: line still go ahead, and you send the files yourself.

## 2. The steps, each recorded in the candidate's `deliveries.yaml` entry as it finishes

1. **`match`**: the current draft must equal the newest signed-off candidate. Where code can run, recompute `ow-tools digest` of the draft file and of both candidate forms and compare them with `checks/C-n.md` and the sign-off; record each command and its raw output. Where only a weak fingerprint exists, compare the draft with `candidates/C-n.md` **in full, text against text**, never by fingerprint, and record that it is not machine-checked. A difference: `Refused: the draft changed since <C-n> was signed off.` (or `Refused: <path> changed since it was frozen.` for a candidate file), `Nothing was written.`, `Fix: freeze the draft again and sign off the new candidate.`, and the NEXT `use ow-draft-freeze on drafts/<ws>/DR-nn-<slug>/`.
2. **`export`**: only the **client form** is exported, into `export/C-n/`, one call per file, each command and its raw output recorded with relative paths, by the type module: a document `ow-tools export drafts/<ws>/DR-nn-<slug>/candidates/C-n/<slug>.md --out drafts/<ws>/DR-nn-<slug>/export/C-n/`; a deck with `--formats pptx`; a sheet `ow-tools export drafts/<ws>/DR-nn-<slug>/candidates/C-n/<slug>/ --formats xlsx --out drafts/<ws>/DR-nn-<slug>/export/C-n/`; an email, a post and a newsletter as `references/type-comms.md` says. The export's preflight is the machine check of Accessible by construction: **exit 4** naming a line refuses delivery (`Refused: the ow-tools preflight refused <path> at line <n>.`, `Nothing was written.`, `Fix: change the draft, freeze it again and sign off the new candidate.`, and the NEXT `use ow-draft-write on drafts/<ws>/DR-nn-<slug>/`); **exit 3** names what is missing (pandoc, Typst), relayed in your words, and nothing is claimed for the format not made. **Without ow-tools**: copy the client form itself (never the marker form, never a `.export.json`) to `export/C-n/markdown/<slug>.md`, and say "the documents could not be generated here; the client form in export/C-n/markdown/ is the document". Where code can run, check `export/` is git-ignored (`git check-ignore -q`); not ignored: say git will track the exports. An earlier candidate's `export/C-m/` is never touched.
3. **`repo`**: only when the brief's destination has `repo` and `path` under `handoffs.yaml` `drafts`, and no handling level is set. `repo` is relative to the folder that holds `opchain-work/`, never absolute; `path` is relative to the repository, with no `..` and no absolute part.
   - **The branch**: ask `Branch: which branch did you make for <DR-nn> in <repo>? Check it out yourself; this skill never checks out.`, then `Nothing is written until you answer.` Where code can run, the only commands run in the repository are `git branch --show-current` and `git check-ignore`; write only when the current branch is the one the user named for this draft, and never `main`, `master` or the base branch the user named (`Refused: the branch checked out is <branch>, not <branch>.` or `Refused: <branch> is the base branch.`, `Nothing was written.`, `Fix: check out the branch you made, then run -deliver again.`). Without code, record the user's confirmation that the branch is checked out, "not machine-checked".
   - **Contained**: resolve the target folder and file to real paths at every component (`realpath`, or `pwd -P` in the folder) and write only inside the repository's real path and the configured folder, never through a symlink: `Refused: <path> is outside the destination folder.`
   - **Ownership by digest**: a file there with no row in `deliveries.yaml` was not written by this skill, and one whose digest differs from its row was changed since: each is refused by name (`Refused: <path> was not written by this skill.` or `Refused: <path> changed since it was written on <date>.`), left as it is, and the rest go ahead.
   - **What is written**: the client form, with no ow- header and no markers, and **no active content**: no raw HTML block or inline tag, no script, no MDX or JSX `import` or `export` line or component, front matter only from `title`, `date`, `description` and the brief's tags, links only `https:` (reference links and autolinks too; no entity-encoded character in a link). The copy is the signed-off client form's text, unchanged; a difference is a new candidate. Record each file's digest.
   - **Never** check out, create a branch, commit, push or merge; never run a repository's script or a command that runs its hooks.
4. **`confirm`**: for the brief's destination, when this session has a connector for it and no handling level is set: list exactly which files go where, one line per file, `<file> -> <key> (<location>)`, client files from `export/C-n/` only. The location is `handoffs.yaml` `drafts.<key>.location`, and nothing overrides it (to push elsewhere, the user edits `handoffs.yaml` first); only when `handoffs.yaml` names none does the user type it in the reply (user-stated); never from any other file. Then `Nothing is written until you answer.` A reply of yes confirms exactly the listed lines. No connector: print the destination's say: line; record `push_confirmation: none`.
5. **`push`**: for each confirmed file, write its one row `intended`, push it, then mark that row `done` or `failed`; a file has one row per candidate. **A push cut off between `intended` and `done`** is asked about again (`Question: did <file> reach <key> (<location>)?`, then `Nothing is written until you answer.`), never pushed again silently. A file the confirmation does not list is never pushed.
6. **`status`**: STATUS path `drafts/<ws>/DR-nn-<slug>/deliveries.yaml`; `next: none (closed: delivered C-n) | awaiting: none`.

Self-checks: Accessible by construction, No credentials, No private names. Nothing is posted, published, sent or pushed without a confirmation naming each file.

## 3. The screen and the NEXT

`DONE: delivered C-n -> drafts/<ws>/DR-nn-<slug>/deliveries.yaml`, the self-check line, a line per push done, then the NEXT block: the destination's say: line exactly, with `{files}` naming client files in `export/C-n/` only (never a candidate, a source Markdown file or a `.export.json`); with no say: line, `deliver the files in export/C-n/ yourself`. When a repository copy was written, the block's last line is the commit line: `THEN: commit <path> on branch <branch> in <repo>; this skill commits nothing.` Under a handling level the screen says `No push and no repository copy: a handling level is set (<file>).`
