# ow-tools 1.3.1 — security manifest

Generated by `scripts/gen-ow-tools-manifest.mjs`. Do not edit by hand.

## Runs code

**Yes.** `bin/ow-tools` (POSIX sh) starts `lib/cli.mjs` (Node.js, built-in modules only; no npm dependencies, so Claude Code runs no npm install). `python/diarize.py` runs in a private Python 3.12 environment built by uv from the committed `python/uv.lock`. The SessionStart hook runs `bin/ow-tools hook session-start`, which reads `opchain-work/STATUS.md`, checks PATH and a few files for readiness (it never starts a browser or Python), and writes nothing.

## Network

By verb. Every other verb, `ow-tools doctor` and the SessionStart hook open no socket.

| Verb | Reaches | What it sends |
|---|---|---|
| `capture` (1.1.0) | The system resolver, once per host name in `allowed_origins`, before launch (a loopback or link-local answer refuses the plan). Then only those origins (https; never loopback in any spelling, never link-local), through the browser, at the addresses ow-tools checked. Every other request the page makes is failed; the browser resolves no other name (a host-resolver map: each allowed name to its checked address, everything else not found), and its own background traffic is turned down by flags. Service-worker fetches and WebSockets are not seen by the request guard (the host map still applies) | Each allowed host name (DNS); what the browser sends to the test environment, including the plan's test data in `fill` steps; never a credential typed by ow-tools |
| `health` (1.1.0) | `api.osv.dev`; `registry.npmjs.org`; `data.iana.org` (the RDAP list, at most once in 30 days); the RDAP server that list names over https for each listed domain; the hosts and URLs `health.yaml` lists. pip-audit, when it runs, makes its own requests to `api.osv.dev` (`--vulnerability-service osv`), outside the address rules below | The name and version of each public-registry package with a plain semver version (POST to OSV, in batches; one package per POST to `/v1/query`, at most 50, when a batch answer doesn't line up); each such direct dependency's name (GET to npm); each listed domain (RDAP); a TLS handshake to each listed host; a GET to each listed URL. Never a package that resolves to a private registry, a git URL, a tarball or a path, the project's own npm scope or a listed private scope, a cookie or an auth header. Loopback, private, link-local, CGNAT, metadata and other special-use addresses are refused after DNS resolution (IPv6 outside global unicast included), and the socket is checked before a byte is sent; redirects are not followed. `--no-network` sends nothing |
| `scan-secrets` (1.3.0) | Nothing. ow-tools opens no socket, and the git it runs (gitleaks' git included) refuses every transport (`protocol.allow=never`), never fetches a missing object (`GIT_NO_LAZY_FETCH=1`) and never prompts; a test points a partial clone's promisor remote at a local listener, which sees no connection | Nothing |
| every other verb | Nothing | Nothing. ffmpeg is limited to the `file` protocol, so a recording that is really a playlist can't open a network address |

The user-run setup steps that `ow-tools doctor` prints reach: Homebrew (packages, and the Chrome cask), huggingface.co (the Whisper model; the pyannote model with the user's token), PyPI and python-build-standalone via uv (the Python environment).

| Screenshots `<step-id>.png` (0600, 1.1.0) | The `shots/` folder given with `--out` (refused unless git-ignored when inside a repository) |
| The capture profile (0700, 1.1.0) | `$OW_TOOLS_HOME/capture/<workstream>/`: the browser's profile, holding the test session the user signed in to (cookies encrypted with the keychain key). Its caches are removed before and after every run; after a production run its cookies and site storage are wiped too, on an interrupt or kill signal as well, and a run killed outright leaves `.ow-tools-production-pending` so the next run wipes first; `.ow-tools-run.lock` (the running process's id) keeps it to one run at a time; `--delete-profile` removes it |
| The RDAP list cache (0600, 1.1.0) | `$OW_TOOLS_HOME/rdap/dns.json`, refreshed after 30 days |
| pip-audit's own cache (1.1.0, when it runs) | pip-audit's HTTP cache in the user's cache folder (pip-audit's choice, not ow-tools') |
| Temporary audio, model output, Word and PowerPoint parts | A private (0700) temp folder, removed when the run ends |
| The scan's private copy of the refs (under names of ow-tools' own), the redacted report, git's exit status and error output, and git's temporary merge objects (1.3.0) | `ow-tools-scan-*` in the user's temp folder (0700, umask 077), removed when the scan ends, on an interrupt or kill signal too; a scan killed outright leaves it, and the next scan removes it once its owner process is gone. While git runs, its temporary merge objects there can hold committed text, compressed. No file in the scanned repository is created or changed; git may refresh the timestamps of its pack and object files (it freshens the objects a merge re-creates) |
